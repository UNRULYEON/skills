# ui-sh

Each of the workflows below is independent — match the request to the ONE
file that fits and follow only that file. This is not a joint review like the
`better` skill's holistic mode; there is no "run all nine" case.

| Request shape | Read |
| --- | --- |
| Designing new UI, a page, section, or component from scratch | [design.md](design.md) |
| Adding or improving dark mode on an existing UI | [add-dark-mode.md](add-dark-mode.md) |
| Generating a brand identity or marketing-site mockup board | [brand-kit.md](brand-kit.md) |
| Cleaning up, sorting, or deduplicating Tailwind classes | [canonicalize-tailwind.md](canonicalize-tailwind.md) |
| Extracting existing UI into reusable components | [componentize.md](componentize.md) |
| Creating a dark-mode variant of a standalone raster image | [dark-mode-image.md](dark-mode-image.md) |
| Comparing multiple UI options in-browser with the ui.sh picker | [ideas.md](ideas.md) |
| Adapting an existing UI across mobile/tablet/desktop breakpoints | [make-responsive.md](make-responsive.md) |
| Converting a screenshot, Figma export, mockup, or wireframe into semantic markup | [markup-from-image.md](markup-from-image.md) |

`design.md` additionally loads [design-guidelines.md](design-guidelines.md),
which indexes the full `guidelines/` rule-file set (colors, typography,
buttons, forms, and more) — load only the specific guideline files that
apply to the request, not the whole set.

No match? These files don't cover the request — don't force it into one of
them.
